# The VGA Game Playbook

A reusable development guide for the "minimal design, minimal features,
maximal fun" clone series, distilled from building *Možnar M.11 — Soška
fronta* (Godot 4.x). This repo is the reference implementation — every
technique below has working code here.

---

## 1. Philosophy

- **The constraint IS the aesthetic.** One anti-aliased line, one smooth
  alpha fade, one off-grid pixel — and the DOS illusion pops. Never cheat.
- **Minimal features, maximal fun**: one core loop done with juice beats ten
  systems. Add helpers (assist modes) as opt-ins, never as defaults.
- **Everything generated from code.** Sprites, fonts, backgrounds, flags,
  icons, sound, music — all built by scripts committed to the repo. The only
  binary assets are generated WAVs and converted period photographs. The
  repo stays diffable and every asset is reproducible.
- **Theme with real history** (Slovene where it fits) and honor it: real
  guns, real places, verified specifications, period photographs.

## 2. Non-negotiable rendering rules

1. **Native 320×200**, integer-scaled up. `project.godot`:

   ```ini
   [display]
   window/size/viewport_width=320
   window/size/viewport_height=200
   window/size/window_width_override=1280
   window/size/window_height_override=800
   window/stretch/mode="viewport"
   window/stretch/aspect="keep"
   window/stretch/scale_mode="integer"

   [rendering]
   textures/canvas_textures/default_texture_filter=0   ; nearest
   ```

2. **Fixed palette.** Declare every color as a hex constant in one autoload
   (`vga.gd`). If a color isn't in the palette file, it doesn't exist.
3. **No alpha gradients, no AA.** Transitions between tones use **ordered
   (Bayer) dithering**. Fades to black use dither masks (§5), not alpha.
4. **Integer pixel positions.** Floor every text/UI draw position. A rect at
   x.5 rasterizes an extra column at native res and glyphs smear (we hit
   this: centered text was mush until `floorf()` in the font renderer).
5. **Uppercase, diacritic-free text** — CP437 never had čšž or umlauts;
   German becomes OE/UE/SS, Slovene drops carons. It reads as authenticity,
   not laziness.
6. **Chunky everything**: particles are 1–2 px rects, lines are runs of
   rects, circles are fine (they rasterize hard-edged at 320×200).

## 3. Project skeleton

```
project.godot          # settings above + autoloads + config/version
main.tscn              # ONE minimal scene: root Node2D + main.gd
src/
  main.gd              # state machine: splash -> title <-> help / battle
  gamestate.gd  (G)    # scores, mode, options; ConfigFile persistence
  lang.gd       (L)    # localization table + t(key); persisted choice
  vga.gd        (Vga)  # palette constants, bayer(), hash01(), fade masks,
                       #   procedural background painter
  pixfont.gd    (Pix)  # 5px pixel font atlas + draw/center/shadow API
  sfx.gd        (Sfx)  # WAV pool player + music player with loop
  title.gd  splash.gd  help.gd  battle.gd  ... (scene nodes built in code)
assets/sfx/*.wav       # generated by tools/
assets/img/*.png       # converted period photos
assets/icon/           # generated icon set (.png sizes + .ico)
tools/                 # Python generators: gen_sfx.py gen_music.py
                       #   make_*_photo(s).py make_icon.py
dist/                  # linux .desktop + install.sh
docs/  (.gdignore!)    # screenshots, this playbook — excluded from import
build/ (gitignored)    # export output + release zips
```

- **No .tscn zoo** — nodes are `Script.new()`-ed and wired by code; scenes
  in text stay reviewable and merge-friendly.
- **Autoloads** are the engine room: G (state), L (language), Vga (look),
  Pix (text), Sfx (audio). Battle/title/help are plain Node2D scripts that
  the main state machine swaps as `current` (connect signals BEFORE
  `add_child`, advance scenes via `call_deferred`).

## 4. Palette method

Build small ramps per material, muted and warm-grey, ~4 steps each:

- **Sky**: 5–6 bands, dark top → cream horizon (`6e6a78 … eedebc`).
- **Terrain**: surface / mid / dark / deep ramp (`9a8e7c 786c5c 5a5044
  423a30`), plus snow pair, grass pair, scorch (`201a14`).
- **UI**: steel panel (`23262c`) + bevel highlight/shadow (`4e5560` /
  `121418`) + amber text (`e4d8ac`) + dim (`8a8578`). Every panel gets a
  1px light top/left and dark bottom/right bevel.
- **Fire ramp**: white → yellow → orange → red → dark red for explosions.
- **Team accents**: one saturated color per faction; gun sprites need
  CONTRAST against terrain and sky (we had to darken the grey gun to
  gunmetal and saturate the green one — test sprites against every
  background they can stand on).

## 5. Dithering toolkit (`vga.gd`)

- **Bayer 4×4** threshold matrix; `bayer(x,y)` returns 0..1.
- **Band gradients**: for each pixel, find fractional band position; take
  the next band's color when `frac > bayer(x,y)`. Used for sky, sun halo,
  clouds.
- **Dither fades**: pre-build N mask textures (black where
  `bayer < (i+1)/N`) at 160×100, draw scaled ×2 — chunky DOS fade without
  per-frame pixel loops. Clamp the fade timer's delta (`minf(delta, 0.05)`)
  or slow first frames fast-forward the whole splash.
- **hash01(x,y)** integer hash for per-pixel material noise (rock speckle,
  paper grain) — deterministic, no RNG state.
- **Photos are the exception**: quantize with **no dithering** (32-shade
  ramp) — Floyd-Steinberg speckle on photos reads as dirt ("black dots").

## 6. Pixel font (`pixfont.gd`)

- 5 px tall, variable width (1–5 px), glyphs declared as `#`/`.` string
  rows in a dictionary; atlas built once at startup; drawn white and tinted
  via modulate.
- API: `draw`, `draw_c` (centered), `draw_shadow(_c)` (1px dark offset —
  use shadows on any text over gameplay/sky, bare text only inside panels).
- Scale by integers only (×2 HUD headers, ×3 titles).
- Add glyphs as needed (we added `'` and `^` late); unknown chars render a
  hollow box so omissions are visible, not invisible.

## 7. Generated art

- **Sprites**: ASCII maps, one char per palette slot (`1` dark, `2` mid,
  `3` light, `4`/`5` accents), per-team color dictionaries. Keep every row
  the same length (a stray 15-char row in a 14-wide sprite silently
  truncates).
- **Rotating parts** (barrels): draw as tapered runs of 2–3 px rects along
  the angle vector from a pivot — reads perfectly at native res.
- **Backgrounds**: layered sine-sum ridge silhouettes with snow caps,
  dithered sun disc and cloud blobs. One `make_sky(rng)` reused by title
  and battle keeps the world coherent.
- **Photographs** (Pillow pipeline): grayscale → crop (cut watermark bars;
  stock-agency watermarks dissolve completely at ~176 px wide and 32
  shades) → LANCZOS resize → autocontrast(cutoff=1) → GaussianBlur(0.4) →
  quantize to a 5-stop sepia ramp interpolated to 32 entries,
  `Dither.NONE` → paste on black if pillarboxed. Only use PD-era source
  photographs.
- **Icon**: 32×32 pixel art built with PIL primitives on a dithered sky,
  nearest-scaled to 16…512 + multi-size `.ico`. Wire `config/icon`, call
  `DisplayServer.set_icon()` at runtime, ship `.desktop` + `install.sh` in
  the Linux zip (raw ELF binaries can't embed icons); Windows `.ico` via
  `windows_native_icon` needs rcedit installed at export time.

## 8. Generated audio (Python stdlib only)

- 22050 Hz mono; master chain: normalize → `tanh` soft clip → **quantize to
  8-bit levels** (store in 16-bit WAV) — this quantize is the "Sound
  Blaster" crunch.
- SFX archetypes: *boom* = lowpassed noise burst + decaying sine rumble;
  *shot* = fast pitch-sweep sine + noise; *click/beep* = short square;
  *thud* = low sweep; *sting/win* = square arpeggio. Small pitch
  randomization (`0.92–1.08`) on play stops repetition fatigue.
- **Music**: compose an original loop — square-wave lead (25% duty, light
  vibrato, per-note envelope) over root–fifth march bass and noise snare on
  the off-beats; a 4-chord lament (Am–G–F–E) carries a lot of mood in 8
  bars. Loop via the player's `finished` signal (no import fiddling).
- Player pool (8 voices round-robin) + a dedicated music player in `Sfx`.

## 9. Localization (`lang.gd`)

- One dictionary: `key -> {lang -> string}`; `L.t(key)` with English
  fallback; language list + native display names; choice persisted with
  `ConfigFile` (`user://settings.cfg`).
- Numbers/formulas stay universal; compose with `%` and localized labels.
- **Flags as 12×9 procedural textures** (tricolors are loops; add a
  distinguishing mark when two flags collide — our Slovene flag needed a
  tiny Triglav shield to not read as Russia).
- Budget pixels: check the widest language (usually German) against every
  layout; abbreviate rather than shrink.

## 10. Game-feel defaults

- Screen shake (world container offset, ±1–2 px), gun recoil, muzzle
  flash, debris + smoke particles, trail pixels — cheap and essential.
- **Precision inputs**: for values players fine-tune, use discrete key
  repeat — tap = exactly 1 unit, ~0.35 s delay, slow then fast repeat,
  Shift halves it. Continuous `value += rate*dt` frustrates at unit scale.
- **Anti-repeatability**: pure determinism lets players replay a solution
  forever. Drift the environment each turn (wind ±3 with gusts) and add
  small per-shot dispersion (±0.6°, ±1% v0).
- **Helpers are per-player and honest**: trails/feedback must show YOUR
  last shot, never the opponent's; a "calculator" should compute from the
  real constants, and measured feedback should be integrated from the
  actual flight, not re-derived.
- **Teach with the real equations**: help screens that plot from the same
  constants the game integrates can never lie — but those constants are
  then duplicated (battle / help / HUD calc) and must be kept in sync.
- **Helpers state the ACTION, not just the measurement**: our drift
  calculator stayed "confusing" until it gained a green AIM line showing
  the correction (arrow + magnitude upwind) instead of only the drift. If
  the player must mentally invert your number, print the inverted number.
- **Display values are not internal values**: both gunners read the same
  elevation scale (0 = toward the enemy) via a display-only mirror for the
  right-hand gun — physics and the Rx untouched. Fix presentation at the
  presentation layer.
- **Difficulty through historical constraint** beats penalties: hard mode
  locks power to the gun's five real propellant charges — "pick the
  charge, lay with the angle" is how real batteries worked; the constraint
  teaches instead of punishing. Constrain the human, not the computer.
- **Overlays dock relative to each other, not to screen edges**: once
  several helpers coexist (calculator, soldier line, touch buttons), fixed
  positions collide. Draw panels in dependency order, record their edges
  (`_calc_bottom`), and dock the next overlay beneath. On touch devices
  the bottom of the screen belongs to thumbs — informational overlays go
  to the top.

## 11. Dev harnesses (build these on day one)

- **`-- --autotest`** (via `OS.get_cmdline_user_args()`): both sides run by the prescription software (Rx),
  banners shortened, **fixed dt = 1/30** (headless delta is wall-clock and
  useless), prints every shot/hit/round to stdout. Run headless, grep for
  `SCRIPT ERROR`. This catches 95% of breakage in seconds.
- **`-- --shots`**: muted Rx demo that saves screenshots. Needs
  `DisplayServer.window_set_vsync_mode(VSYNC_DISABLED)` + `Engine.max_fps`
  (compositors throttle unfocused windows) and a frame-numbered timeline;
  add state-triggered captures (e.g. first AIM state) for phase-specific
  shots. To photograph human-only UI in an Rx demo, force its visibility
  condition in a **scratch copy** of the project (nothing to revert).
- **Batch mode**: `--autotest --matches=N` plays N matches in one process.
  Set `OS.low_processor_usage_mode_sleep_usec = 1` in autotest — headless
  otherwise idles ~7 ms a frame (a match drops from minutes to ~2 s).
  Hundreds of rounds turn "the Rx sometimes acts odd" into numbers: parse
  the shot log for impossible angles, shots per round, script errors.
- **Input harness**: a scene extending `main.gd` that feeds fake
  `InputEventKey` / `InputEventScreenTouch` / `InputEventJoypadButton`
  events through `Input.parse_input_event` on a frame (or state-relative)
  timeline. Run it in a scratch copy with `config/use_custom_user_dir`, so
  toggles it flips never land in the player's settings.
- **Text check** (`tools/text_check.tscn`): every localized string vs the
  font atlas (missing glyphs) and vs its slot width (screen, buttons, 2x
  titles, label columns), with `%s`/`%d` replaced by realistic values.
- Screenshot at native res, upscale ×2 nearest for humans.

## 12. Touch & controllers (one project, one build)

Touch support lives **in the canonical project** — SKODA 305 first shipped
it as a separate fork (main → fork re-syncs) and merged it back in v1.10.0
once it had proven that it never changes the desktop experience. A
fork only duplicates every gameplay change; skip it. The touch layer is
thin, because of one architectural decision:

- **Synthesize keys, don't duplicate logic.** A `CanvasLayer` autoload
  draws VGA-style buttons and turns touches into the *same events the
  keyboard produces*: edge-triggered keys (fire, menu, weapon-TAB) via
  `Input.parse_input_event(InputEventKey)`, polled keys (angle/power) via
  a `held` dictionary OR-ed into a `_pressed_key()` helper in battle. All
  input behavior — precision tap-repeat, tap-vs-hold semantics — works
  verbatim with zero duplicated code.
- **Menus are touch-native**, not button-covered: any scene exposing
  `tap_at(pos)` gets direct taps. Dense menu rows (12 px ≈ 3.6 mm on a
  phone) use **select-then-confirm** — first tap moves the highlight,
  second activates; screen-sized zones (manual paging, banners, splashes)
  need nothing. Do the millimetre math: 1 game px ≈ 0.3 mm; interactive
  targets want ≥ 24 px (~8 mm).
- **One build serves everyone**: the overlay activates only when
  `DisplayServer.is_touchscreen_available()` (a `--touchui` flag forces it
  for testing/screenshots). Desktop players see nothing; mouse clicks ride
  the tap path as a free bonus. On itch this means a single
  browser-playable file with "Mobile friendly" ticked.
- **Runtime scale toggle**: `Window.content_scale_stretch`
  INTEGER ↔ FRACTIONAL, persisted, smart default = fractional iff
  touchscreen (phones fill the screen, desktops stay pixel-perfect).
- **The iOS trinity** (every one cost a bug report):
  1. Set `input_devices/pointing/emulate_mouse_from_touch=false` when you
     handle both touch and mouse events yourself — otherwise every tap
     arrives twice and self-confirms your two-step menus.
  2. Audio stays locked until the first gesture; music that auto-started
     while locked remains silent forever — retrigger it on the first tap.
     The iPhone ring/silent hardware switch also mutes web audio.
  3. iPhone Safari has **no element Fullscreen API** — itch's fullscreen
     button is inert there; the remedy is itch's "Mobile friendly"
     full-window presentation.
- **Self-documenting UI**: give the manual a touch page that draws replica
  buttons with the same style code — documentation that cannot drift.
  Show it only when the overlay is active (build the manual's page list at
  `_ready`), so desktop players don't page through controls they lack.
- **Gate web-only fixes**: the first-tap music retrigger runs only under
  `OS.has_feature("web")` — on native builds the mouse rides the tap path,
  and an unconditional retrigger would restart the tune on the first click.
  A real key press counts as the unlocking gesture too.
- **Show touch buttons after the first touch**, not merely when a
  touchscreen exists — touchscreen laptops are usually driven by keyboard.
  A button over a gun goes see-through (alpha 0.4) instead of hiding it.
- **Edges from events, holds from polling.** Every source must deliver key
  *events* (touch synthesizes press on finger-down, release on last
  finger-up — count fingers per key). Discrete actions (power step, weapon
  tap) act on the press event; per-frame polling only drives repeats and
  hold timers. Polled edges lose any tap shorter than a frame.

**Controllers** use the same trick — a gamepad is just another keyboard
(`Pad` autoload, `pad.gd`):

- Map joypad buttons/stick to key press *and* release events via
  `Input.parse_input_event`; those update `Input.is_key_pressed()` too
  (from the next frame), so polled controls work unchanged.
- Track `"device:control" -> key` and keep a key down while ANY control
  holds it (D-pad + stick, two pads). Stick: hysteresis (press > 0.5,
  release < 0.3). Release everything on disconnect and on focus loss.
- Resolve context-dependent buttons at press time, release the same key.
  Never map a dangerous key to an easy button: B must not be ESC on the
  title (quit) or in battle (abandon) — START is the deliberate menu key.
- Mark synthesized events (`ev.device = 77`) so the layer can tell its own
  keys from a real keyboard: the last *real* device decides the hints.
- Hints follow the device: `L.t(key)` returns `key + "_pad"` when it exists
  and the pad is active — add `_pad` variants only for strings that name
  keys.

## 13. Validation & release

- Keep a known-good editor binary; always pass an **absolute `--path`**
  (a drifted shell cwd makes Godot report "no main scene defined").
- Order: `--import` headless (a killed import corrupts `.godot` — delete
  and re-import if weirdness appears) → autotest → export.
- `export_presets.cfg` committed: Linux + Windows, `embed_pck=true` (one
  file per platform), `exclude_filter="docs/*,tools/*,assets/icon/*,dist/*"`,
  plus a Web preset with `variant/thread_support=false` — no-threads WASM
  runs on itch.io without cross-origin-isolation headers. Web builds need
  guards: no `DisplayServer.set_icon`, no quit option (`OS.has_feature("web")`).
  The itch zip must have `index.html` at its root. Pin
  `renderer/rendering_method="gl_compatibility"` project-wide: the web
  can't run Forward+/Mobile, and Compatibility suits 2D pixel games on
  every platform anyway.
- Release ritual: bump `config/version` (title screen reads it) →
  CHANGELOG entry → export all targets → **smoke-test the built binary
  with the autotest** → zip with README + CHANGELOG + LICENSE (+ Linux:
  icon png, .desktop, install.sh) → refresh docs/ screenshots from the
  built binary.
- macOS specifics: universal/arm64 export requires
  `textures/vram_compression/import_etc2_astc=true`; exports land AS a
  zip — **rename it before any `rm *.zip` packaging cleanup** (we deleted
  a fresh export twice); ship unsigned with a right-click-Open note, or
  wire rcodesign later.
- The export target directory must exist before a headless export.
- Releases carry the series pseudonym in LICENSE and every export
  copyright field (macOS Info.plist etc.) — the author's real name never
  ships in artifacts.
- `docs/` gets a `.gdignore`; `build/` is gitignored.

## 14. Gotchas ledger (paid for in debugging)

| Gotcha | Rule |
|---|---|
| `var x := a.b + 1` on an untyped node fails to parse | explicit types when reading from `Node`-typed vars |
| Centered text smears | `floorf()` positions in the font renderer |
| Splash self-skips | clamp per-frame delta during asset-generating scenes |
| Import hangs / blank game | absolute `--path`; nuke `.godot` after a killed import |
| Screenshots stall | disable vsync in demo mode |
| ASCII sprite row length mismatch | rows must equal `body[0].length()` |
| Physics constants drift apart | grep for duplicates when tuning (battle/help/calc) |
| Checking a helper mutated state | actions on key-release with a hold threshold (TAB tap vs hold) |
| Docs PNGs imported by engine | `.gdignore` in docs/ |
| Clamped random walk camps at the bounds (wind felt "always from one side", ~20% of turns at max) | reflect off bounds + ease extremes toward zero; verify with a histogram sim (`tools/wind_sim.gd`) |
| Runtime SubViewports ignore the project's nearest-filter default (logos rendered soft, ~70 colors) | set `texture_filter = TEXTURE_FILTER_NEAREST` explicitly on the drawing node; audit assets by unique-color count + binary alpha |
| PIL animated GIF with per-frame ADAPTIVE palettes goes psychedelic after frame 1 | quantize every frame to ONE exact global palette (Dither.NONE) |
| iPhone taps fire twice and self-confirm two-step menus | `input_devices/pointing/emulate_mouse_from_touch=false` when handling touch + mouse yourself |
| iOS: music that auto-starts before the first gesture stays silent forever | retrigger music on the first tap; the ring/silent hardware switch also mutes web audio |
| itch fullscreen button dead on iPhone | iOS Safari has no element Fullscreen API — tick itch's "Mobile friendly" instead |
| Texture created inside a draw callback renders blank | the draw command runs later — keep the texture referenced in a member var |
| macOS universal export refuses with "ETC2 ASTC" error | enable `textures/vram_compression/import_etc2_astc` |
| Fresh macOS export vanishes during packaging | it exports AS a zip — rename before `rm *.zip` |
| Fixed-position overlays collide as helpers multiply | dock overlays off each other's recorded edges; on touch, the bottom belongs to thumbs |
| Two keys/fingers in one frame award a round twice | scene switches are deferred, so the old scene still hears input: one central "switch pending" guard in main ignores repeats until the new scene exists |
| Taps shorter than a frame vanish (slow web frames, quick fingers) | act on press events; poll only for holds/repeats |
| Shell landing differs by frame rate; a stall throws shots far off | integrate flight in fixed slices (1/120 s) and cap frame dt (0.1 s); march collision steps <= 1 px (`ceili`) |
| Rx correction that only ever moves one way traps itself (lobbed past vertical, fired backward ~6% of rounds) | clamp aim to the foe's side, reset "stuck" counters on non-consecutive misses, test with 150-match batches |
| `shake_mag = max(old, new)` never decays | reset the magnitude when the shake ends |
| Freshly copied `.godot` cache crashes the first `--import` | delete `.godot` in scratch copies; fresh imports are clean |
| Wrongly typed value in settings.cfg throws and skips the rest | check `typeof()` before converting loaded values |
| A supplied "pixel art" picture is 2.5 MB, 57k colors, soft (drawn at a non-integer ~4.5x) | box-sample it to its true grid (~320x240), ONE global palette (48 colors, no dither), store at an exact integer multiple (3x); boot splash `stretch_mode=0` + `use_filter=false` shows it crisp and centered — the web loader reuses it as `index.png` (45 KB instead of 2.5 MB) |

## 15. New-game checklist

1. Copy skeleton: `project.godot` display block, autoloads (G/L/Vga/Pix/Sfx),
   `main.tscn`, tools/, dist/, `.gitignore`, `docs/.gdignore`.
2. Re-theme `vga.gd` palette ramps; keep the Bayer/hash/fade toolkit.
3. Keep `pixfont.gd` as-is; add glyphs when a string needs them.
4. Day one: wire `--autotest` and `--shots` before gameplay grows.
5. Generate placeholder SFX from the archetypes; compose the theme late.
6. Localize from the first string — retrofitting L is the expensive path.
7. Splash → title → game loop with banners; version on the title screen.
8. Decide mobile early: if the game will ever be touched, keep menu tap
   targets generous and plan the touch layer (§12) — the key-synthesis layer
   retrofits cleanly only if inputs go through polled keys and key events.
9. Ship: version bump, changelog, export all targets, binary smoke test,
   zips with LICENSE (pseudonym attribution), screenshots — and update
   this playbook with anything new it cost you.
